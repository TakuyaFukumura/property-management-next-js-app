# 機能要件定義

## 1. 文書の目的

本書は、MVPで必要な主要機能を、実装・設計に落とし込める粒度で定義する。

対象は主に以下の機能群である。
- 物件管理
- 部屋管理
- 収支管理
- 修繕履歴管理
- ダッシュボード
- 要対応一覧

## 3. 機能要件詳細

## 3.1 PM-PROP-001 物件一覧表示
- 概要: 保有物件を一覧表示し、物件ごとの基本情報と状態を確認できる
- 利用者: オーナー
- 主な表示項目:
  - 物件名
  - 物件種別
  - 所在地
  - 部屋数
  - 稼働状況サマリー
  - 当月収支サマリー
  - 要対応件数
- 主な操作:
  - 物件検索
  - 並び替え
  - 物件詳細への遷移
- バリデーション: なし（一覧表示）
- 例外時の挙動: データ取得失敗時はエラーメッセージを表示する

## 3.2 PM-PROP-002 物件登録
- 概要: 新しい保有物件を登録できる
- 利用者: オーナー
- 入力項目:
  - 物件名（必須）
  - 物件種別（必須）
  - 郵便番号
  - 住所（必須）
  - 購入日
  - 購入価格
  - 土地建物メモ
  - 保有状況
  - 備考
- 処理内容: 入力値を検証後、物件データを保存する
- 完了条件: 物件一覧に反映される
- バリデーション:
  - 物件名必須
  - 住所必須
  - 購入価格は0以上
- 例外時の挙動: 入力エラー時は項目単位でメッセージ表示

## 3.3 PM-PROP-003 物件編集
- 概要: 登録済み物件の情報を更新できる
- 利用者: オーナー
- 入力項目: PM-PROP-002に準ずる
- 処理内容: 対象物件の情報を更新する
- 完了条件: 詳細画面と一覧に最新情報が反映される

## 3.4 PM-ROOM-001 部屋一覧表示
- 概要: 物件配下の部屋一覧を表示し、稼働状況を確認できる
- 利用者: オーナー
- 表示項目:
  - 部屋番号
  - 間取り
  - 面積
  - 賃料
  - 共益費
  - ステータス
  - 契約終了予定日
- 主な操作:
  - ステータス別絞り込み
  - 部屋詳細/編集遷移

## 3.5 PM-ROOM-002 部屋登録
- 概要: 物件に紐づく部屋を登録する
- 利用者: オーナー
- 入力項目:
  - 物件ID（必須）
  - 部屋番号（必須）
  - 間取り
  - 面積
  - 賃料
  - 共益費
  - ステータス（必須）
  - 募集開始日
  - 備考
- バリデーション:
  - 部屋番号必須
  - 面積は0超
  - 賃料、共益費は0以上
- 完了条件: 部屋一覧に反映される

## 3.6 PM-ROOM-003 部屋編集
- 概要: 部屋情報を更新する
- 利用者: オーナー
- 入力項目: PM-ROOM-002に準ずる
- 処理内容: 部屋情報を更新し、関連一覧に反映する

## 3.7 PM-INC-001 収入登録
- 概要: 家賃などの収入を登録する
- 利用者: オーナー
- 入力項目:
  - 物件ID（必須）
  - 部屋ID（任意）
  - 入金日（必須）
  - 対象月（必須）
  - 収入カテゴリ（必須）
  - 金額（必須）
  - メモ
- バリデーション:
  - 金額は1以上
  - 対象月必須
  - カテゴリ必須
- 処理内容: 収入データを保存し、月次集計へ反映する

## 3.8 PM-EXP-001 支出登録
- 概要: 修繕費や税金などの支出を登録する
- 利用者: オーナー
- 入力項目:
  - 物件ID（必須）
  - 部屋ID（任意）
  - 支出日（必須）
  - 対象月（必須）
  - 支出カテゴリ（必須）
  - 金額（必須）
  - 支払先
  - メモ
- バリデーション:
  - 金額は1以上
  - カテゴリ必須
- 処理内容: 支出データを保存し、月次集計へ反映する

## 3.9 PM-SUM-001 月次収支サマリー表示
- 概要: 月次の総収入、総支出、キャッシュフローを表示する
- 利用者: オーナー
- 表示項目:
  - 対象月
  - 総収入
  - 総支出
  - 収支差額
  - 物件別収支
- 主な操作:
  - 月切り替え
  - 物件別絞り込み
- 処理内容: 収支データを月単位で集計する
- 例外時の挙動: 該当データなしの場合は0件表示する

## 3.10 PM-REP-001 修繕履歴登録
- 概要: 修繕対応の履歴を登録する
- 利用者: オーナー
- 入力項目:
  - 物件ID（必須）
  - 部屋ID（任意）
  - 発生日
  - 対応日
  - 修繕カテゴリ（必須）
  - 内容（必須）
  - 費用
  - 対応状況
  - メモ
- バリデーション:
  - 物件ID必須
  - 内容必須
  - 費用は0以上
- 処理内容: 修繕履歴を保存し、物件詳細へ反映する

## 3.11 PM-REP-002 修繕履歴一覧表示
- 概要: 修繕履歴を物件単位で時系列表示する
- 利用者: オーナー
- 表示項目:
  - 対応日
  - 修繕カテゴリ
  - 内容
  - 費用
  - 対応状況

## 3.12 PM-TASK-001 要対応一覧表示
- 概要: 空室、更新予定、未対応修繕などの要対応事項を一覧表示する
- 利用者: オーナー
- 表示項目:
  - 種別
  - 物件名
  - 部屋番号
  - 発生日/期限日
  - ステータス
  - 優先度
- 主な操作:
  - 種別絞り込み
  - 物件詳細への遷移
- 処理内容: 契約情報、部屋ステータス、修繕対応状況をもとに要対応データを生成する

## 3.13 PM-DASH-001 ダッシュボード表示
- 概要: 全体の運営状況を俯瞰するトップ画面を表示する
- 利用者: オーナー
- 表示項目:
  - 総物件数
  - 総部屋数
  - 空室数
  - 当月収支
  - 要対応件数
  - 注意対象物件
- 主な操作:
  - 各一覧画面への遷移
  - 対象月切り替え

## 3.14 PM-CSV-001 CSVエクスポート
- 概要: 物件・収支・修繕履歴などをCSV出力する
- 利用者: オーナー
- 対象: 物件一覧、収支一覧、修繕履歴一覧
- 優先度: Should

## 4. 共通要件

### 4.1 一覧機能の共通要件
- 検索、絞り込み、並び替えができること
- データ0件時に空表示メッセージを出すこと
- PCで見やすい表形式レイアウトを基本とすること

### 4.2 登録・編集機能の共通要件
- 必須項目は明示する
- エラーは項目単位で表示する
- 保存成功時は完了メッセージまたは一覧反映で結果がわかること

### 4.3 モバイル利用時の共通要件
- 閲覧と簡易更新ができること
- 表は横スクロールまたはカード表示で破綻しないこと

---

## 5. フェーズ4時点の結論

MVPでは、一覧・登録・集計・履歴管理・要対応可視化を中心に、個人投資家の運営実務を支える機能群を定義する。
